- 全局快捷键实际按键触发：本宿主注入失败，独立 Win32 热键诊断亦未收到注入按键。注册 / 占用 / 回滚已经实际验证，仍需物理键盘测试，失败证据保留。
- 没有用户提供的真实模型地址 / 凭据，AI 没有连接真实 LLM；已测试真实 HTTP 协议、凭据存取和 Mock Provider，不冒充模型成功。真实模型输出质量和兼容性需用户配置后测试。
- 长期后台资源占用、100 节点编辑器性能、事件风暴和跨设备安装仍需测量。本次短时 Rust 资源采样不含 WebView2。
- 在线签名更新和安装代码签名未配置，没有伪造更新地址。核心本地能力不依赖更新服务。

## 功能边界

- 同一场景自动触发继续每天最多一次；多个环境规则即使符合条件也可能因 V1 自然日去重跳过，决策记录具体原因。手动运行不受自动日限制，但同场景互斥。
- 工作模式切换只提交新工作流，不关闭原模式软件；当前模式不表示所有第三方程序已就绪。某些高负载程序无额外就绪探测。
- V2 工作流顺序与条件分叉，不支持并行、循环或汇合。最多 200 节点、60 分钟。V3 条件最多三层与 64 节点。
- 程序权限不足、受保护进程 / 窗口、自定义窗口、独占全屏可能不可检测或不可移动，按 Unknown / Error 降级。Windows 许可范围外不绕过 UAC。
- 当前应用检测使用完整路径且只检测启用规则指定对象，低频补查意味着停止事件可能最多延迟约一个检查周期；不是完整应用历史监控。
- 断开显示器可按缺失策略回退，但真实多分辨率与 DPI 组合需进一步实机验收。浏览器标签页不是独立 Windows 窗口。
- 历史只保留有限脱敏摘要；已被清理的记录不能回放，不记录原始 Wi-Fi 或窗口内容。清理历史不重置冷却 / 去重。
- JSON 配置备份不默认携带日志；SQLite 升级副本含历史。DPAPI 信任网络不能跨设备直接使用，AI 密钥不导出。
- AI 正式提交当前只支持规则和工作流，解释为辅助文字；本地确定性冲突分析为准，不能把模型推测当事实。生成路径缺失必须补全。

## 可直接继续的工作顺序

1. 依照 [Windows 验收](V3-WINDOWS-VALIDATION.md) 完成物理按键和硬件 / 权限 / 会话事件测试，保存真实报告；若失败针对 Provider / 原生订阅修复并加回归。
2. 使用用户明确配置的真实本地或云端模型，验证自然语言规则 / 工作流、缺参数、恶意响应、超时和发送预览。
3. 整组进程长期资源测试与 100 节点编辑性能，测量后调整低频 Provider 和前端刷新策略。
4. 独立 Windows 10 / 11 设备安装 / 卸载与跨设备恢复，确认 DPAPI 失效提示及 WebView2 引导。

V3.1 可考虑原生进程事件替代补查、规则测试用例保存、多设备显示器稳定标识、导入路径批量修复与更丰富的决策报告。后续签名更新需可信发布源和真实签名配置后再启用。
