# StartFlow V3.1 第五阶段实际测试报告

测试环境：Windows 11 x64，MSVC 2022 / Windows SDK 26100，Rust 1.99，Node 24.16.0，Playwright 1.64.0，已安装 Microsoft Edge。测试使用隔离 debug 数据目录、合成凭据、本地 HTTPS 网站和专用 Win32/UIA 测试应用，没有安装覆盖生产应用或读取用户生产数据库。

源码保留在升级分支 `codex/startflow-v3.1-integration`，GitHub 的 `main` 同步当前交付。原有版本分支、标签、提交历史及项目 `AGENTS.md` 保留；没有改写历史或全局 Git 身份设置。

## 已实现与修复

- 四个登录节点接入既有 Rust 工作流：检查状态、自动登录、等待人工验证、登录结果分支。网页复用 Playwright Sidecar，桌面复用 UIA 工作进程。
- 本机登录授权绑定工作流执行语义、登录配置及凭据版本；导入、AI 草稿和配置变化不能隐式获取授权。
- 失败停止/跳过/人工等待策略，整体及节点超时、取消、真实身份验证和一次自动提交。未知/错误状态不能作为 False 分支继续。
- 修复桌面人工验证返回 `waiting_manual` 时被提前判失败的问题；修复取消返回后错误归类为普通失败的问题。
- 修复已打开浏览器使用旧页面状态，未发现服务器已撤销会话的问题；现在重新探测授权 URL。
- 修复工作流表重建造成不变授权丢失，以及导入引用可能复用旧本机凭据的问题。
- 统一账号中心、工作台和日志的真实登录记录；修复长名称、状态及时间文字溢出，在深浅主题中验证。隐藏主窗口时暂停不必要的登录历史刷新，重新显示时加载最新状态。
- Schema 7 一致性备份和事务迁移，Schema 4 登录规则备份与安全引用映射。普通备份不含密码、Cookie、Profile、令牌及本机登录授权。
- AI 可生成四类登录节点草稿，只发送用户选择的配置 ID、类型及名称，不能读取用户名、凭据引用或密码。

## 文字溢出修复

`LoginHistory` 统一使用有内边距的 `login-history` 面板，限制子元素宽度，名称、状态与时间允许换行，连续长字符串使用 `overflow-wrap: anywhere`。真实 WebView2 深浅主题测试检查容器、记录、文本的 `scrollWidth <= clientWidth + 1`，均通过。

另发现桌面应用页同名记录区域存在三列的最小内容宽度问题，已一并修复：中间列使用 `minmax(0, 1fr)`，子元素允许换行，记录卡片内宽度不超过 560px 时改为单列。使用实际构建的 CSS，在独立 Edge 中对两种主题、300/420/650/950px 卡片宽度共 8 组进行真实布局测量，全部通过。此项是合成长文本的 CSS 布局回归，不冒充原生 UIA 功能测试；最新桌面页样式尚待实际 Tauri 窗口复验。

## 剩余实机验收与兼容限制

1. 在正式版退出后完成 V1/V2/V3 原生回归及凭据 JSON 报告重跑；其中物理快捷键输入若受桌面环境限制须标为未验证。
2. 在没有可用浏览器的普通用户机器验证完整官方 Chromium 下载、取消、重试和磁盘不足错误。
3. 实际安装/卸载、真实 Windows 重新登录、长时间托盘运行、睡眠恢复、物理双屏插拔及不同 DPI。
4. 锁屏、UAC/安全桌面、管理员应用、权限拒绝和损坏凭据库。不会通过模拟键鼠或提权绕过限制。
5. 第三方网页登录及 UIA 框架逐项适配；不保证跨域 SSO、iframe、多页认证、自绘控件、Passkey、扫码或 MFA 自动完成。
6. 真实 AI Provider 和密钥由用户配置，本地核心功能不依赖 AI；没有提供免费云端服务。

数据库迁移、授权和敏感数据说明见 [集成与安全指南](V3.1-INTEGRATION.md)。测试均以实际结果为准，未通过或未运行的项目没有归类为通过。
