# V3 Windows 实机验收

“已验证”仅指报告中的实际操作；Mock、Dry Run 和缺失标识回退不替代物理设备事件。使用测试场景和受控程序，先备份配置。以下待验证项不会自动更改 Windows 权限、断网、锁屏或拔显示器。

| 验收 | 当前证据 | 继续验证步骤 |
|---|---|---|
| 1 旧版本升级 | 非空真实 V2 样本、逐表 Rust 测试、真实 NSIS V2 → V3 安装升级通过 | 在含个人真实配置的另一设备升级，检查全部实体 / 历史 / 自启 |
| 2 Wi-Fi 触发 | 实际 WLAN 当前连接可读取；默认关闭、授权开关和 DPAPI 存储已测 | 添加信任 SSID，启用建议规则；切换指定网络，稳定五秒后检查决策；批准后检查真实运行 |
| 3 双屏触发 | 实际显示器读取与规则模拟通过 | 接入第二屏，确认稳定等待后产生显示器规则决策，不在瞬间盲目移动窗口 |

## 全局快捷键

真实 RegisterHotKey 注册、重复组合、系统占用及失败回滚通过。当前执行宿主的 `keybd_event` 注入未触发热键，独立 RegisterHotKey 诊断同样失败；保存失败报告，不能标记实际按键触发通过。

在普通交互桌面设置两个组合：一个启动受控场景，一个打开命令面板。隐藏主窗口，用物理键盘按下，核对运行日志 trigger=shortcut 与真实程序回执；命令面板只能出现一个。再用其他程序占用组合，确认保存失败与原注册保留。若物理按键仍失败，记录系统环境与插件回调，继续定位，不能仅改 UI 状态。

## 长时间性能

当前仅有十秒采样，单独 Rust 进程 CPU / Working Set **不包含 WebView2**。不可据此宣布后台 CPU / 内存达标。需记录整组 StartFlow + WebView2 进程，测试至少一小时空闲、窗口隐藏、重复网络事件、显示器插拔、睡眠恢复、多规则、快速暂停 / 恢复；记录峰值 / 平均 CPU、内存、决策延迟、队列是否有界及重复执行数。

## 登录与睡眠

自启登记 / 实际查询及模拟 `--autostart` 启动已测，实际注销再登录仍待操作。先启用登录自启、登录规则，注销再登录，核对单实例、隐藏策略与延迟；普通手动打开不得重复执行登录规则。睡眠跨越计划时间，恢复后只在补执行窗口且通过去重时运行，检查 V1 / V3 同日协调。
