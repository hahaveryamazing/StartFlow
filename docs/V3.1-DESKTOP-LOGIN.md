# V3.1 第四阶段：Windows 桌面应用登录

基线为第三阶段 `c2a8804`，增量分支 `codex/startflow-v3.1-desktop-login`。只增加桌面登录，不改变场景、工作流、调度或网页登录执行逻辑。没有进行第五阶段开发。

## 使用方式

1. 在「账号与凭据」添加 **Windows 应用账号**，绑定目标程序实际完整 EXE 路径。LNK 不能作为本阶段的应用身份。
2. 自行启动应用，点击「配置应用登录」，或进入「桌面应用登录」选择账号并开始录制。
3. 读取窗口列表，选择绑定 EXE 的目标窗口；刷新控件，选择账号 Edit、密码 Edit 和登录 Button。
4. 在目标应用中自行完成一次登录，再刷新控件，选择成功标识与显示用户名的 Text 控件。身份文本必须与绑定用户名完全一致。可选择失败提示及人工验证控件。
5. 优先保存 AutomationId + ControlType，并可增加最近有标识父级的 AutomationId；没有稳定标识的输入框转为人工登录。非输入控件可明确使用 Name。编辑规则后先测试定位，再保存。
6. 自行退出目标应用的登录会话，点击「授权并测试登录」并确认。密码最多提交一次。已有绑定账号的有效会话只复用，不读取密码；已有其他账号会话会停止，要求人工切换。

录制采用可视化窗口/控件列表，不是屏幕坐标或鼠标轨迹录制器。成功页面与登录表单应属于同一窗口身份；遇到结构变化需重新录制。更新账号密码会轮换凭据引用，需要在编辑/重新录制页面重新保存配置。会话检查不会自动授权。

## 实现与安全边界

- Rust Microsoft UI Automation：`IUIAutomation`、`IUIAutomationValuePattern::SetValue`、`IUIAutomationInvokePattern::Invoke`。不使用 SendInput、键盘粘贴、鼠标坐标或任意脚本作为后备方案。
- 非 UI 的 COM MTA 运行于 StartFlow 自身的私有工作进程。固定命令行只有 `--desktop-login-worker`，请求/响应采用匿名 stdin/stdout 管道；无开放端口、无密码参数、无密码 IPC 返回。UIA 卡住时由父进程期限与 Windows Job Object 清理，最多四个工作进程。
- 父进程从 SQLite 加载并验证账号和配置。操作前及账号、密码填写与提交前再次核验 HWND、PID、进程创建时间、EXE 路径、窗口类和精确标题；控件树的进程 ID 必须属于目标应用。进程创建时间以字符串经过前端，避免 JavaScript 整数精度丢失。
- 必须是当前用户会话的普通 Default 输入桌面；拒绝更高完整性级别的进程和系统凭据/UAC 窗口。不申请 UIAccess 或管理员权限。每次操作前再次检查桌面，不尝试穿越锁屏或安全桌面。
- 只有明确授权、目标与控件检查通过后，工作进程才从 Windows Credential Manager 读取绑定密码。密码输入框必须 `IsPassword`、可写且支持 ValuePattern，登录按钮必须可用且支持 InvokePattern。
- 不调用 ValuePattern.GetValue 或 TextPattern 来读取输入值。Edit 与密码控件的 Name 不被录制。规则默认优先保存 ID，避免把动态文本固化到配置。运行消息由程序生成，不保存应用错误正文、控件树或密码。
- StartFlow 持有的密码、UTF-16 缓冲和 BSTR 会在释放时清零；无法保证 Windows COM 内部、操作系统或目标应用自身的复制缓冲也被清零。自动填写本身必然把密码交给用户明确选择的可信应用。
- 成功必须同时满足成功控件可见、身份文本等于绑定用户名、密码控件已消失。仅调用按钮不等于登录成功。
- 明确人工验证控件或常见验证码、扫码、MFA、Passkey、Hello 提示出现时停止自动提交。已经提交后出现验证也不会再次尝试。检测不能保证识别所有第三方验证界面；不清楚的流程应人工登录。
- 同一 EXE 登录互斥；每账号五分钟最多保留一次尝试预算，重启与系统时间回退不会重置。账号变更/删除与授权填写互斥，避免密码轮换竞态。
- 主窗口隐藏后 Rust 登录检查继续运行。彻底退出会由 Job 清理工作进程，不终止目标第三方应用。异常退出的 `running` 记录下次启动标为 `interrupted`，不自动重试。
- 所有新增 Tauri 命令复用账号模块的本地主窗口来源检查。命令面板/远程页面不得访问。没有扩大 Tauri capabilities。

依据 Microsoft 的 [UI Automation 线程要求](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)及 [UI Automation 安全边界](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)。

## 数据与迁移

SQLite 从版本 5 升到 **6**。新增 `desktop_login_configs`、`desktop_login_runs`、`desktop_login_attempts`，不删除或重写旧表。配置只保存账号/凭据引用、窗口身份及控件定位元数据。

已有数据库先通过 SQLite backup API 保存一致性升级备份，再在事务中创建表、索引、外键和版本记录；失败回滚且不创建空库覆盖用户数据。删除账号级联删除其配置与尝试预算，保留不含密码的运行历史。历史最多 200 条，界面显示最近 30 条。

普通 JSON 导出仍不包含账号凭据、网页/桌面登录配置或浏览器会话。SQLite 升级备份包含登录元数据，不包含 Windows 凭据密码。工作流/场景的原有导出、备份及恢复流程保持原行为。

## 已实测支持及限制

本机 Win32 合成测试应用已验证：标准 Edit/密码 Edit/Button/Text 的真实识别和填写提交；成功与身份核验；会话复用与过期；其他账号会话拒绝；重复窗口、重复输入框、过期进程身份和不存在控件拒绝；失败、超时、提交前/后 MFA 提示；只读密码框转人工；窗口隐藏后后台运行；无响应提供程序超时隔离；录制界面保存与深浅主题；元数据、JSON、日志不含合成密码。

尚未实测：真实第三方应用各自的 UIA 实现；Windows 真实锁屏/解锁；真实 UAC/安全桌面；管理员/受保护应用的拒绝路径；安装包安装/卸载。相关路径已有正常权限检查，但不能把代码检查等同于实机验收。

本阶段不支持没有稳定输入框 AutomationId、没有 ValuePattern/InvokePattern、输入密码后换窗口/进程、动态改变窗口标题、分步骤/多页登录、自绘/游戏控件、嵌入浏览器的跨进程控件树，以及无法显示可靠账号身份的会话。不保证兼容 Qt、Electron、WPF、UWP 等所有实现；需要逐应用验证。拒绝或失效时提示人工登录/重新录制，不回退坐标操作。人工验证等待不会后台持续点击；完成后可主动检查会话。
