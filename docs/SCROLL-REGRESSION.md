# 页面滚动修正与验证

日期：2026-10-10。

## 修改

- 为 html、body、React 根容器和应用外壳建立明确的高度约束，不再仅依赖 `100dvh`。这避免不支持动态视口单位的 WebView2 将页面撑出窗口。
- 为主内容区设置可收缩的 Flex 尺寸和最小高度，滚动发生在窗口内；侧栏仍然独立滚动。
- 提高深浅主题滚动条的可见度，并支持聚焦内容区后使用 PageDown / PageUp。
- 为弹窗高度保留 `100vh` 兼容回退。

本次未改动数据库、凭据、任务执行器和调度器。

## 实际验证

`npm test`：8 个测试文件、44 项测试通过。

`npm run build:native-test`：Windows MSVC Debug 构建成功。

`npm run bundle -- --target x86_64-pc-windows-msvc --features custom-protocol`：Windows x64 NSIS 构建成功。产物复制为 `release/StartFlow_3.1.0_scroll-fix_x64-setup.exe`，约 29.63 MiB；保留原阶段五安装包。

`npm run test:native:scroll`：32 项检查通过。测试连接实际 Tauri WebView2，以 CDP 注入滚轮及键盘事件；使用隔离的合成数据库，暂停自动化，不运行用户任务。

检查覆盖：刚打开的工作台；全部 16 个导航页面及 AI 助手；滚动到内容底部并返回；深浅主题；1280×800 和 1024×700 视口；侧栏独立滚动；PageDown；不支持动态视口单位的兼容性情形；打开与关闭账号弹窗后恢复滚动。内容较短的页面使用明确标识的长内容布局夹具，结果记录说明是否添加夹具。

详细结果见 [scroll-native-results.json](scroll-native-results.json)。小视口使用浏览器视口模拟，没有实际调整 Windows 窗口尺寸。

## 安装版差异与实机验收

最初隔离 WebView2 的 CDP 滚轮测试也能滚动。用户再次报告失效后，检查实际运行进程的可执行文件版本，确认其仍为 **3.0.0**（文件时间 2026-10-08），尚未运行新修复版。这个差异解释了为何此前测试通过，但用户当前窗口仍然失效；不将其解释为已经查明旧版所有底层输入问题。

用户从托盘退出后，校验修复包 SHA-256 并执行原位安装，安装器退出码为 0。安装文件及桌面、开始菜单快捷方式指向的可执行文件均确认为 **3.1.0**。随后打开安装后的程序，核对实际运行路径、3.1.0 文件版本、主窗口标题和响应状态。

用户在新窗口实际测试鼠标滚轮，明确反馈 **「左右两侧都能滚动了」**。这属于用户执行的 Windows 实机验收，不能与 CDP 自动化输入混为一谈。电脑操作工具仍无法初始化，自动化工具没有执行物理鼠标输入验证。卸载测试、不同显示器及其他鼠标设备未验证。

## 空闲隐藏与透明度优化

2026-10-10，在原修复基础上继续优化左右两个滚动区域：滚动或鼠标移入时短暂显示滚动条，停止活动 1.2 秒后隐藏；鼠标留在区域内不移动时也会隐藏。活动滑块使用主题次要文字颜色，40% 不透明度；轨道透明。只改变原生滚动条外观，保留滚动、键盘访问及稳定的滚动条占位，避免内容宽度变化。Windows 高对比度模式保留系统滚动条，优先保证可访问性。

通过被动的 scroll / pointerenter 监听更新 DOM 标记，不拦截滚轮默认行为，不刷新 React 页面；每个区域只有一个可重置的短时计时器，卸载时清理监听和计时器。

前端 44 项测试通过，生产前端和 Windows Debug 构建成功。实际 Tauri WebView2 自动化检查扩展至 36 项，深浅主题分别验证两侧从隐藏状态滚动、显示半透明滑块、空闲后隐藏、再次滚动及内容不跳动。详细结果见 [scroll-transient-native-results.json](scroll-transient-native-results.json)，截图见 [scroll-idle-light.png](scroll-idle-light.png)。这次新增的自动隐藏交互由 CDP 测试，尚未另行取得用户鼠标实测反馈。

Windows x64 NSIS 构建成功，保存为 `release/StartFlow_3.1.0_scroll-polish_x64-setup.exe`（31,068,019 字节）。用户退出应用后完成原位安装，安装器退出码 0；验证安装后 EXE 确实包含本次编译的前端与样式资源标识，随后重新打开安装后的应用。
