# V3.1 第三阶段：可视化网页登录录制器

日期：2026-10-09。增量分支 `codex/startflow-v3.1-login-recorder`，基线为第二阶段浏览器按需准备版本 `ec15a3d`。本阶段没有改变工作流、规则或调度核心，没有开始第四阶段。

## 使用方式

1. 在「账号与凭据」添加 HTTPS 网页账号，密码由 Windows Credential Manager 保存。
2. 点击该账号的「配置网页登录」或「录制登录流程」。填入同一网站的精确登录页面地址，打开独立录制浏览器。若浏览器尚未准备，在「网页登录」先检测 Edge / Chrome；不可用时可明确选择下载专用 Chromium。
3. 在向导点击“选择账号输入框”，再在浏览器点击对应控件；依次选择密码框和登录按钮。蓝色高亮提示当前选取目标，选取点击不会提交表单。Esc 暂停选择，回到向导可重新选择。
4. 点击“测试当前页面定位”。账号框、密码框、按钮必须唯一、可见且属于同一个精确 HTTPS POST 表单。多匹配、类型错误或不安全的表单会阻止下一步。
5. 点击“进入人工登录”，在已验证网站自行输入账号密码。录制器没有读取 Windows 密码库的接口，也不读取输入值。录制浏览器使用临时隔离会话，不借用日常浏览器或正式登录 Profile。
6. 登录后分别点选专有的成功元素与账号身份元素，再测试定位。身份元素可见文字必须严格等于账号的用户名，且页面没有可见密码输入框。不能以“点击过按钮”替代成功判断。
7. 设置配置名称和 3～120 秒超时，保存。修改已有配置须确认替换；多次保存同一草稿使用相同 ID。保存不执行登录。
8. 点击“授权测试登录”，确认后调用第二阶段引擎。从 Windows 凭据库读取绑定密码，通过私有管道提交最多一次，保留账号独立 Profile。录制时的临时 Cookie 不转入该 Profile。已有正式会话仍优先复用。

「网页登录」每张配置卡提供“测试定位 / 重新录制”、删除及高级 JSON 编辑。旧 CSS 配置可以在定位表单中编辑；测试从当前页面重新验证表单目标。删除定位后必须重新选取或编辑、测试。发现 `locator_invalid` 时会显示“定位失效，请重新配置”，没有自动退回宽泛匹配或选择第一个元素。

## 实现与权限

- `automation/web-login/picker.mjs`：固定浏览器脚本，闭合 Shadow DOM 提示与高亮，仅把点击坐标发送到绑定。没有 input/change 录制、键盘记录、Cookie/Storage 读取、页面内容转储、HAR、视频或生产截图。
- `recorder.mjs`：受控 Node 服务派生定位。优先 Role / Label / Placeholder / TestId，必要时选择唯一 CSS；不生成 nth/first 定位，不把成功或身份的可见账号文字写进规则。拒绝明显动态 ID、长哈希、URL 和控制字符。采用 Playwright [官方定位接口](https://playwright.dev/docs/locators)，所有候选在实际页面检查唯一性和元素类型。
- `locators.mjs`：录制测试与正式登录共用定位与表单检查，执行时使用实际 ElementHandle 验证，不在编辑器模拟登录。
- `src-tauri/src/web_login/recorder.rs`：单个录制会话、固定工作进程、私有 stdin/stdout、Windows Job Object、心跳和有界协议、30 分钟录制上限。关闭、异常或退出清理浏览器及工作进程。
- IPC 只有 `web_recorder_start/snapshot/command/close`；仅可信本地主窗口可调用。命令只允许选取、定位测试、人工登录和返回登录页，未知字段、脚本命令和密码字段均拒绝。普通查询只返回定位和状态元数据。
- HTTPS 精确 Origin、无用户信息/查询参数/片段、同源精确 POST 地址、禁止额外窗口/下载/对话框/Service Worker/WebSocket。导航响应阶段检查重定向，阻止向未知 Origin 跳转与 307/308 POST 重放。录制阶段禁止自动 POST，人工登录仅允许一条已验证表单 POST；返回登录页显式重置临时会话。
- 正式登录仍保留单次自动提交、持久冷却、人工验证等待、账号隔离和实际成功/身份检测。凭据引用发生变化时要求重新绑定并保存；不悄悄使用旧引用。
- 生产版不打开自动化端口。测试脚本在 **debug** 构建、显式测试环境变量和固定本地证书 SPKI 下使用 9233/9234，仅控制合成测试站。发布 Rust 不发送 CDP 测试字段或证书豁免。

这些防护限制配置和提交的范围，不能把第一方网站本身视为可信密码保险箱。授权后密码交给该 HTTPS 网站，其页面脚本属于网站自身的信任边界；不要向不信任的网站授权登录。网站 DOM 属性和定位规则仍需用户检查，不用捕获页面输入来推断或过滤秘密。

## 数据兼容

SQLite 保持版本 **5**。已有 `web_login_configs.payload` JSON 能保存扩展，不增加无必要的数据表或迁移，也不重写旧配置。新增配置使用 `schema_version: 2`、类型化 `locators` 和 `credential_ref`；没有这些字段的第二阶段配置按版本 1 读取并执行。原场景、任务、规则、日志、布局、快捷键、主题和凭据表保留。

新的定位 JSON 只存类型、控件规则、Origin、表单地址、超时和 UUID 引用，不包含密码、Cookie 或令牌。未保存录制仅存内存，不跨重启恢复。普通配置导出仍排除账号和网页登录配置；专用浏览器 Profile 和录制临时会话不进入普通备份或 AI。跨设备凭据不可移植，需要重新录入。

旧 V1～V4 数据继续使用现有升级迁移，迁移前 SQLite 一致性备份、失败回滚；版本 5 不需要额外迁移。新增测试验证旧 JSON 原字节保留与新配置共存，原有带数据升级及失败回滚测试也重新执行。

## 支持范围与仍需验证

- 支持主文档内同 Origin HTTPS POST 表单：单个账号 / 密码框、提交按钮、可辨识的成功与准确账号身份元素。带 Label / Role 等稳定属性的动态 ID 页面已测试；未作过度宽泛选择器猜测。
- 不支持 HTTP、跨域 SSO / OAuth、多步骤用户名后密码页面、iframe 登录、无可验证 form 的纯 AJAX 登录、必须跨域加载的控件，以及多次 POST 的 MFA 录制流程。跨域资源被拦截，部分网站可能无法完整渲染。会明确失败，不放宽 Origin 或绕过验证码。
- 验证码 / 扫码 / MFA / Passkey 不会由录制器自动处理；正式引擎出现时停止自动提交、等待人工验证。依赖多页 / 多次请求的站点须保持手工登录，当前录制不承诺兼容。
- 成功身份必须显示绑定用户名；只显示昵称、头像或脱敏手机号的网站无法在当前严格策略下证明账户身份。控件不可唯一识别时需选取其他元素或使用经过测试的 CSS。
- 不自动记录事件序列或输入，不执行录制生成的脚本。录制只产生登录定位配置。选取与表单测试不能证明第三方服务器真实完成认证，因此正式运行仍再次核验成功和身份。
- 当前已验证本地合成站点与 Windows Edge；未向任何真实第三方站点提交凭据。各站实际验证、企业浏览器策略、MFA / Passkey 设备交互、长时间常驻性能和第三阶段安装/卸载仍待专项测试。

本阶段到此结束；未来独立阶段可评估显式授权的多步骤表单和身份规则扩展，不能通过放宽默认安全边界解决兼容问题。
