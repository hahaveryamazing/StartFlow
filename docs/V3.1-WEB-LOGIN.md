# V3.1 第二阶段：网页登录

在第一阶段提交 `f54bd90` 的凭据库上增量开发，升级分支为 `codex/startflow-v3.1-web-login`。保留旧任务启动器、调度、场景、工作流、环境规则、布局、主题和 AI 模块。没有录制器，没有新增任意脚本接口，也没有继续第三阶段。

## 本阶段实现

- 「网页登录」页面：绑定已有 HTTPS 网页账号，创建、编辑、验证及删除明确的选择器配置；深浅主题、加载/错误状态、真实执行反馈、关闭专用浏览器。
- “仅检查会话”不授权密码读取。“授权登录”先展示网站、账号、单次提交和 Cookie 保留说明，确认后才允许本次读取。保存配置不执行。
- Rust 校验账号 UUID、网页账号类型、精确 Origin、HTTPS、无内嵌凭据/查询参数/片段、CSS 选择器、超时上限和未知字段。普通查询与事件永不返回密码。
- 每个账号独立目录 `browser-profiles/<账号 UUID>`，位于应用数据目录。路径由后端生成，拒绝符号链接/Windows 重解析点；不接受用户任意 Profile 参数，不接触 Chrome/Edge 日常资料。
- Playwright 启动持久化专用 Chromium。先检查可见成功标识与账号身份文字；二者满足且无可见密码框/人工验证才确认成功。有效会话直接复用，不请求密码。
- 登录表单必须有唯一、可见、可写的用户名框、密码框和提交控件，属于同一个明确的 HTTPS POST 表单。填密前及每一步再次校验；提交事件也验证目标。
- 私有浏览器仅允许配置的精确 HTTPS Origin，拦截跨域请求、未知主页面、弹出页、下载和 WebSocket。额外通过 Chromium 响应拦截检查重定向 Location，阻止跨 Origin 重定向与 307/308 密码 POST 重放。
- 最多一次自动填密/点击；按账号持久化五分钟授权填密预算，重新打开配置、重启、关闭正在提交的浏览器、改变配置 ID 不会重置预算。系统时钟倒退时安全阻止。会话复用不受预算限制。
- 显式成功、会话复用、过期、失败、超时、阻止、等待人工、未授权、冷却、中断状态。验证码/扫码/MFA/Passkey 使用配置标识与内置常见控件检测；标准 WebAuthn 请求也转入人工等待，不替用户完成验证。未知页面无法确认结果时超时，不重试。
- 人工验证后只观察真实成功与身份，不再次提交密码。不登录时人工等待最多五分钟，已登录专用浏览器最长八小时；用户可随时关闭。关闭主窗口到托盘不会停止 Rust 服务。

## 安全架构

主窗口调用类型化 Rust Commands → 受控浏览器管理器 → 固定 Node/Playwright worker → 专用浏览器。没有开放服务端口，没有前端密码 getter，没有通用 shell/任意代码执行命令。

Rust 只在本次明确授权、页面校验后发来的单次 nonce 请求中调用第一阶段的 Windows `CredReadW`。再次核对账号版本及凭据引用，再经继承的匿名 stdin 管道传输。密码不放在进程参数、环境变量、事件、stderr、SQLite 或普通 JSON 中。返回管道只接受有大小限制的类型化状态、nonce 和心跳，拒绝额外秘密字段。运行时脚本与应用编译时嵌入的脚本内容必须一致；版本/浏览器文件缺失时拒绝启动。

子进程环境清理后只传必要的 Windows 路径和专用浏览器路径，禁用 Playwright 调试日志，stderr 不向日志转发；无 Trace/HAR/截图记录。Chromium 通过调试管道通信，不开放 CDP 端口。Windows Job Object 绑定 Node 和浏览器子进程，心跳超时或软件退出时清理，最多同时三个账号浏览器，同账号不允许重入。

Rust 秘密缓冲区使用 Zeroizing；JavaScript 密码仅短暂存在于受控进程内存中，使用后移除引用，并清空可访问的密码框。不能声称 JavaScript GC 能保证所有内存副本被物理擦除；操作系统转储和恶意的同用户进程不在该隔离机制可防御范围内。用户明确授权的网站必须可信，同 Origin 的被攻陷页面不可能靠选择器被证明安全。

**专用 Profile 本身包含敏感 Cookie/会话资料。** 仅保留在当前用户的数据目录，沿用浏览器与 Windows 的本地保护，不宣称所有缓存均加密。应用的 SQLite、JSON 导出、AI 上下文、日志、配置备份均不包含 Profile、Cookie 或密码。浏览器密码保存功能禁用。不要把整个应用数据目录当成普通可公开分享的配置包。

删除登录配置/账号不等于清理已有浏览器 Cookie。本阶段保留会话目录；彻底退出应用后，可在设置显示的数据目录中手动删除相应 `browser-profiles/<账号 UUID>` 以清除该会话。跨设备恢复不能复制凭据引用来获得密码；应重新录入凭据并登录。

## 数据升级

SQLite 版本 **4 → 5**。新增 `web_login_configs`、`web_login_runs`、`web_login_attempts`，分别存选择器/账号引用、固定状态与时间、账号冷却时间。配置外键绑定账号，账号删除级联删除配置和预算，历史运行摘要保留。原表及密码引用保持不变。

旧库升级前使用 SQLite 一致性备份，DDL/版本号/外键校验在事务内提交。备份失败停止升级，DDL 失败回滚，不创建空库替换。启动将未完成登录标记中断，保留已验证的历史结果，不自动恢复登录。普通配置导出仍为 Schema 3，**不包含账号、网页登录配置及 Profile**；迁移 SQLite 备份可以包含账号和登录配置元数据，但不含密码/Cookie。该阶段不新增凭据跨设备导入。

## 运行时与打包

Windows 10/11 x64、Node **24.16.0**、Rust **1.99.0**、VS C++ 工具链/Windows SDK、WebView2。锁定 Playwright **1.64.0**，由其安装匹配的浏览器（build 1248，Chrome for Testing **156.0.8078.4**）。不依赖用户安装的 Chrome/Edge，也不使用它们的日常 Profile。

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
npm ci
npm run browser:install
npm run browser:prepare
npm run desktop
```

`browser:install` 仅构建/开发准备时从 Playwright 官方来源下载配套浏览器；`browser:prepare` 将当前固定 Node、Playwright/核心包、worker/engine、完整浏览器及许可证复制至 `src-tauri/resources/browser-runtime`。已有相同内容跳过复制，文件损坏或不同则重新复制。运行中的不同版本二进制仍需先关闭再更新，不强行终止用户浏览器。

运行时清单记录版本与关键文件 SHA256，供构建诊断；清单不是独立签名。Node LICENSE 随包，Playwright LICENSE/NOTICE、浏览器原有 ABOUT/credits/terms 保留。构建目录忽略进 Git；发布应分发安装包，不能只复制一个 StartFlow EXE。

```powershell
npm run bundle
# 或完整检查、测试及显式 x64 打包
./scripts/build.ps1
```

Tauri resources 保留 `resources/browser-runtime/...` 目录，发行版从应用资源目录加载；调试版使用仓库准备目录。安装包带 Node/浏览器，终端用户不需要 Node/npm；首次缺 WebView2 时仍使用原有微软安装引导。首次准备需要网络，安装后的本地自动化运行时不再下载；实际登录自然需要访问目标网站。Playwright/浏览器安全升级需一起升级依赖、Rust 版本检查、浏览器资源并重建安装包。Windows runner 已增加浏览器安装、真实本地 HTTPS 浏览器测试和资源打包。

参考：[Tauri 2 资源打包](https://v2.tauri.app/develop/resources/)、[Playwright 持久化 Context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)、[Playwright 重定向拦截限制](https://playwright.dev/docs/api/class-page#page-route)、[Chromium Fetch 响应拦截](https://chromedevtools.github.io/devtools-protocol/tot/Fetch/)。

## 支持范围和待验证

本阶段是**明确配置的同 Origin HTML POST 登录流程**，不是万能网站登录器。选择器和成功身份文字必须根据网站真实 DOM 配置；页面模板不能直接用默认选择器声称某网站受支持。异步无表单登录、iframe 登录、跨 Origin SSO、带查询参数的 OAuth 流程、外部验证资源尚不支持自动完成，安全限制可能阻止它们。跨域验证码框可识别人工等待，但外部资源仍被阻止；不宣称能加载或自动通过所有验证码服务。

扫码/MFA/Passkey 只等待用户在专用浏览器完成；不保存 OTP、设备 PIN、Passkey，不模拟真实厂商验证成功。未知挑战可能只能表现为超时，所以必须配置人工验证标识。检测到有效会话才复用；点击提交不算成功。

旧网页启动任务继续使用既有启动器，不会自动使用这些 Cookie。本阶段没有自动登录工作流节点、录制器、自动授权调度或会话跨设备导入。真实网站兼容性、实体安全钥匙、手机扫码、企业策略、安装/卸载与长期浏览器资源占用需目标环境验证。既有 V1/V2/V3 单元及迁移回归不能代替全部系统登录、快捷键、显示器插拔实测。
