# V3 架构与运行约束

```
Win32 原生事件 → EnvironmentProvider → Context Snapshot
                                       ↓
本地规则 / 时钟 → 四值评估 → 优先级与冲突 → Automation Coordinator
                                       ↓
手动 / 计划 / 快捷键 ───────────→ 既有 Execution Coordinator
                                       ↓
                          Workflow Engine → Task Launcher / Window Manager

AIProvider → 结构化草稿 → Schema / 引用验证 → 用户确认 → 禁用配置
```

Environment Provider 不启动任务；规则评估器不调用 Windows；模拟器只返回决策；AI 没有 Task Launcher 或任意系统工具接口。

## 模块接口

- `context`：可用性独立枚举与强类型字段，Context Schema，权限遮罩、脱敏、稳定状态指纹。
- `environment`：可注入 Provider、Windows 网络 / WLAN / 显示器 / 电源 / 会话 / 指定进程、HTTPS 探测，原生订阅 RAII 注销及有限事件合并。
- `rules`：强类型条件树、Schema / 引用校验、可注入时钟、四值评估、确定性优先级 / 冲突解析与本地解释。
- `automation`：后台服务、持久化事件 / 冷却 / 覆盖、统一动作提交、确认建议、历史回放、事务仓储和 Tauri Commands。
- `diagnostics`：按本地日期范围查询真实执行和决策统计，不读取应用操作内容。
- `ai`：独立协议 Provider、受保护凭据、发送预览令牌、响应限制、草稿验证和正式禁用配置提交。
- 前端 `features`：环境、模式、规则、模拟器、决策、隐私、AI、统计独立页面，业务评估全部通过类型明确的 Rust Commands。

## 安全边界与有界运行

配置最多 256 规则、64 模式、64 信任网络；条件树最多三层与 64 节点。启用 HTTPS 服务最多八个，连接超时与整体探测超时受限，不跟随重定向。规则总体评估有耗时检查。所有图和规则执行前再次验证。

原生事件通道容量 16，重复事件合并，默认至少等待五秒稳定。用户指定进程仅按启用规则的完整 EXE 路径检查，补查间隔 15 秒；一般状态补查 60 秒。权限开关会立即遮罩旧快照，同时重建需要权限的订阅。

暂停期间继续必要的状态刷新，不提交新自动场景，不积压历史执行队列；恢复只评估最新状态。手动操作仍经过场景互斥。V1 / V2 保留最多四个并发执行、自动场景自然日去重和任务失败隔离。

事件声明在动作提交前事务持久化；有业务身份的定时事件使用规则与本地日期标识。每次评估保存原始规则配置版本、事件、脱敏快照、运行约束和决策，配置版本共用存储，避免每条决策重复复制配置。清空历史不删除配置、冷却或去重声明。

历史默认保留 30 天，最多 1000 环境事件 / 快照、5000 决策；独立事件声明保留有界 30 天 / 20000 条。历史回放使用保存的规则版本和运行约束，不使用当前规则假装还原过去，也不执行动作。

请求确认最多有效十分钟。批准时重新检查规则版本、启用状态、真实最新环境、稳定性、暂停 / 覆盖 / 冷却和并发，原建议状态在协调器锁内原子领取，重复确认不会重复启动。

异常退出后旧执行标记 interrupted，保留自动去重，不从中间节点恢复。正常关闭窗口隐藏到托盘不影响后台线程；彻底退出停止服务并注销原生事件。

## 前端状态

状态来自 Rust 快照、真实执行事件和 SQLite。旧 / 新快照独立并行命令读取，避免嵌套数据库锁。可见窗口按事件合并更新并低频刷新，隐藏后停止不必要刷新；监听器卸载时释放。React Flow 与 AI 页面按需加载，主题切换使用设计 Token。

模式切换只启动新内容，不默认关闭旧程序。当前模式表示最近选择 / 匹配模式，不证明对应第三方程序已完全就绪。窗口状态与权限限制沿用 V2 服务。
