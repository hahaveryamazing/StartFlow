# StartFlow V3.1 第五阶段：工作流登录整合

本阶段在 `bcbc8fa` 的第四阶段实现上增量开发，分支为 `codex/startflow-v3.1-integration`。未重建项目，未改动用户生产数据库。历史阶段的安装包和报告保留。

## 实现范围与使用

四个登录节点由现有 Rust 工作流引擎执行：

| 节点 | 行为 |
| --- | --- |
| 检查登录状态 | 网页打开或复用绑定账号的专用浏览器；桌面等待已启动应用的唯一窗口，只读检查登录与账号身份。 |
| 自动登录 | 使用绑定的登录配置，经本机工作流授权后最多提交一次；支持停止、跳过或转人工验证。 |
| 等待人工验证 | 只检查用户自行完成的结果，不再次填密或提交；可取消、可超时。 |
| 登录结果分支 | 已验证当前账号进入 True；明确未登录进入 False；错误、未知目标、无权限或定位失效停止，不冒充 False。 |

桌面流程先放置原有「启动应用」节点，再检查登录、自动登录或等待人工验证，然后连接后续节点。网页登录检查本身准备专用浏览器；原有「打开网页」任务仍按其浏览器选择工作，不接管日常浏览器会话。分支须分别连接结束路径，不支持合流或循环。

账号中心继续支持网页与应用账号、一目标多账号、安全新增/更新/删除、配置录制、定位测试、一次真实登录测试。新增统一登录历史；工作台和运行日志展示实际状态摘要，工作流日志保留节点结果和错误。新节点参数面板从真实已录制配置中选择账号，不能在节点中填写密码。

保存包含自动登录节点的工作流后，点击「授权自动登录」。这是对当前工作流及其登录绑定的本机授权，适用于手动、计划和环境触发。修改执行配置、登录规则、账号或凭据版本会使授权失效；拖动画布位置与不相关主题保存不会撤销授权。导入和 AI 草稿不带入授权。授权前仍可只读检查与人工验证。

取消会关闭该节点使用的专用自动化浏览器并停止 UIA 工作进程及尚未执行节点，不终止用户的目标桌面应用。每节点最长等待 3～600 秒，还受工作流整体超时限制；密码自动提交仍受既有五分钟持久化预算限制。

## 前四阶段基线

检查确认安全凭据库、HTTPS Playwright 登录服务、可视化网页录制和 Microsoft UI Automation 桌面录制/登录已有实际实现，原生验收使用合成账号及专门测试应用。第五阶段接入这些服务，没有复制启动器或另建执行引擎。

本阶段修复的关键集成问题：

- 活跃浏览器旧 DOM 不能证明服务器会话仍有效；实时检查重新访问精确授权登录地址，等待登录或未登录证据。
- 工作流取消及整体超时须传给 UIA 隔离进程，避免等待在后台残留；取消优先于工作进程返回的失败状态。
- 扩展数据保存会重建工作流表，必须保留未变化的本机授权，执行语义变化则撤销。
- 授权与配置/凭据版本在真正填密前再次核验，不能沿用已更换的绑定。
- 未知登录状态不参与真假分支，也不能以普通「失败继续」策略绕过该限制。
- 导入必须为账号、配置、凭据引用及工作流引用一致重映射，不能意外复用本机旧密码。

## 数据库、备份与恢复

数据库升级至 **Schema 7**，新增 `workflow_login_grants`，以外键关联工作流。现有场景、任务、调度、日志、环境规则、窗口布局、快捷键和账号表保留。已有数据库升级前通过 SQLite Backup API 创建一致性备份；迁移在事务中执行并校验外键，失败回滚，不创建空库覆盖旧数据。

JSON 配置与自动备份升级至 **Schema 4**，读取旧 Schema 2/3。新增 `login` 元数据段，包含账号名称/用户名/目标/引用和网页、桌面定位规则。**不包含密码、Cookie、浏览器 Profile、令牌或工作流登录授权。**

导入账号总是获得新的账号 ID、登录配置 ID 和凭据引用，工作流同步改写对应引用。导入后需重新输入密码、检查本机 EXE/窗口/网页定位并重新授权；导入不会自动执行。合并或完整替换常规配置均保留现有账号及 Windows 凭据库，避免未经确认删除密码；完整替换也不会把备份中的引用挂到旧密码。旧账号可在账号中心逐项删除。界面预览展示登录配置数量及缺失凭据提醒。

## 安全审查

- 普通查询、历史、节点结果、事件及 JSON 仅返回类型化元数据和状态，不提供获取明文密码接口。
- 密码只在用户提交保存时进入受控 IPC，存入当前用户 Windows Credential Manager；执行时由后端按已绑定配置取用。Node/UIA 通过私有匿名管道通信，固定命令行不携带密码，生产自动化服务不开监听端口。
- 账号管理与授权接口验证可信本地主窗口；命令面板不能管理凭据。Tauri capabilities 未增加任意 shell、远程网页、浏览器调试或全文件系统权限，CSP 保留本地来源限制。
- 浏览器 Profile 按账号和浏览器家族隔离，不使用用户 Chrome/Edge 主 Profile。现有 HTTPS、精确 Origin、表单目标、唯一输入框和提交目标验证继续生效；外域重定向和失效控件不能填密。
- 桌面复用完整 EXE、进程创建身份、窗口和控件关系验证；锁屏、UAC、安全桌面、扫码、验证码、MFA、Windows Hello 交给用户，不绕过权限。
- AI 仅接收用户明确选择的登录配置 ID、类型和名称，不读取密码、凭据引用、用户名或浏览器会话。新增模型节点白名单和引用验证，保存草稿不产生授权。实际模型服务仍需用户自行配置，本阶段协议测试服务不是真实模型。
- 登录结果日志只记录验证状态、是否自动提交及执行 ID。测试检查合成密码未进入 SQLite/WAL、普通 JSON、WebView 存储、事件和日志。

## Windows 构建与运行时

```powershell
npm ci
./scripts/build.ps1
# 或已准备依赖时：
npm run bundle -- --target x86_64-pc-windows-msvc --features custom-protocol
```

NSIS 默认产物：`src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/StartFlow_3.1.0_x64-setup.exe`。第五阶段独立交付副本、大小与 SHA256 见 `release/StartFlow_3.1.0_phase5_manifest.json`，避免覆盖历史阶段产物。

安装包包含受控 Node 24.16.0、Playwright 1.64.0、录制与登录脚本，终端用户无需自行安装 Node。**不包含浏览器本体**：优先实测探测现有 Edge/Chrome 的必要协议能力，使用独立 Profile；没有可用浏览器时由用户点击下载官方专用 Chromium，支持取消及重试。不会静默下载或调用用户主 Profile。下载浏览器需要网络与额外数百 MB 空间；已有可用浏览器可跳过下载。缺少 WebView2 时 NSIS 使用微软下载引导。

普通用户安装，无自动提权，不绕过 UAC。未配置代码签名和在线更新。安装包生成不等同于所有机器的安装/卸载验收。

原生脚本串行执行，只使用显式 debug 测试目录、合成密码和临时 HTTPS/Win32 程序；不要在它们运行时并行重建同一个 EXE。V1 调度回归保存并恢复精确的原 Windows 自启注册值，不覆盖正式安装路径。测试结果及待验证项目见 [第五阶段实际测试报告](V3.1-PHASE5-TESTS.md)。

最近登录记录在账号中心和桌面应用页面均允许长文字换行，窄桌面记录卡片自动改为单列。修复已包含在第五阶段安装包中；已安装的旧版不会自动获得源码修改。

只支持能可靠识别输入框、提交目标、成功元素和账号身份的网站，以及提供稳定 UIA 控件与账号身份元素的桌面应用。第三方自绘框架、跨域 SSO、复杂 iframe、Passkey/扫码/MFA 和管理员应用不保证自动完成；需要人工验证或重新录制。浏览器会话保存不保证网站不会主动注销或撤销会话。

锁屏/UAC、真实重新登录、睡眠恢复、双屏物理插拔、权限拒绝和任意第三方应用仍需对应设备的实机验收。不得把专门测试应用通过扩展为所有第三方应用兼容。
